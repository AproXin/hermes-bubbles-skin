# 提示词：优化 Bubbles Skin 工具调用状态卡片的嵌套层级问题

## 背景

我在为 Hermes Desktop 开发一个名为 `hermes-bubbles-skin` 的皮肤（蓝色玻璃拟态风格），目前用纯 CSS（`bubbles.yaml` 里的 `customCSS`）覆盖 Hermes 原生 UI。最近发现工具调用（tool call）和状态行（status row）在对话流中出现了严重的**多层嵌套边框 / 背景**问题，视觉上非常拥挤。

## 当前问题（截图证据）

以下三种情况在对话流中反复出现：

### 问题 1：工具调用卡片三层嵌套

以 "已搜索文件" 为例，当前 DOM 渲染出来是这样的：



```
┌─ 外层大卡片（蓝色玻璃背景 + 边框 + padding）─────────────┐
│  ┌─ 中层卡片（又一层蓝色玻璃背景 + 边框）──────────────┐  │
│  │  [▼✓ 已搜索文件]  ← 第一个标签（小胶囊）              │  │
│  │  ┌─ 内层卡片（第三层蓝色玻璃背景 + 边框）─────────┐  │  │
│  │  │  [🔍 已搜索文件 ▼]  ← 第二个标签              │  │  │
│  │  │  ✕                                           │  │  │
│  │  │  TOOL PAYLOAD ▼                              │  │  │
│  │  │  ┌─ 代码块（又一层深色背景）─────────────┐    │  │  │
│  │  │  │  "path": "/Users/..."               │    │  │  │
│  │  │  └──────────────────────────────────────┘    │  │  │
│  │  └─────────────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```



* 同一个 "已搜索文件" 标签出现了 **2\~3 次**

* 蓝玻璃背景 + 边框被重复绘制了 **3 层**

* 每层之间还有额外 padding，导致内容区被压缩

### 问题 2：错误 / 警告状态的红色边框双层叠加

以 "已运行命令" 和 "技能加载失败" 为例：



```
┌─ 外层红色光晕边框 ──────────────────────────────┐
│  ┌─ 内层红色/粉色背景卡片 ────────────────────┐ │
│  │  [⚠ 已运行命令 ▼]                         │ │
│  │  ✕                                        │ │
│  │  TOOL PAYLOAD ▼                           │ │
│  │  ┌─ 深色 Arguments 代码块 ──────────────┐ │ │
│  │  │  "command": "cd ~/.hermes/..."      │ │ │
│  │  └──────────────────────────────────────┘ │ │
│  └────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```



* 红色边框 + 红色背景被画了两层，视觉上像 "框中框"

* 错误状态的红色过于刺眼，和 Bubbles 的蓝玻璃风格不协调

### 问题 3：结果类状态也重复嵌套

"结果不可用"、"Skill Manage" 等状态行同样出现：



* 小胶囊标签 → 中层容器 → 内层卡片，三层

* 同一个状态文字重复 2\~3 次

## 期望效果

我希望达到的视觉目标是：



```
┌─ 统一的工具调用卡片（只画一层）──────────────────────────┐
│  [▼✓ 已搜索文件]                          [✕ 关闭]      │
│  ─────────────────────────────────────────────────       │
│  TOOL PAYLOAD ▼                                          │
│  ┌─ 代码内容（深色背景，仅此一层）─────────────────┐     │
│  │  "path": "/Users/yuanxxx/.hermes/..."          │     │
│  └────────────────────────────────────────────────┘     │
└──────────────────────────────────────────────────────────┘
```

具体要求：



1. **只保留最外层一层卡片边框 + 背景**，中间层容器的背景和边框全部透明 / 去除

2. **标签只出现一次**，最内层那个小胶囊标签（带 ✅/❌ 图标的）保留，外层重复的同名标签去掉

3. **TOOL PAYLOAD 展开区的代码块**保留深色背景，但和外层卡片之间不要又套一层框

4. **错误 / 警告状态**：不要画两层红色边框。外层只保留柔和的红色光晕 / 左边框色条，内层用半透明红背景即可，整体融入蓝玻璃主题

5. 保持 Bubbles 的设计语言：Frosted Glass + 蓝色调 + 柔和圆角 + backdrop blur，不要变成纯黑 / 纯白

6. 不要影响用户消息气泡（右侧蓝宝石气泡）和助手消息气泡（左侧白雾玻璃气泡）的现有样式

7. 不要影响 composer-status-stack（输入框上方的任务列表）的现有样式

## 技术约束



* 这是 Hermes Desktop 的 skin 系统，通过 `bubbles.yaml` 里的 `customCSS` 字段注入 CSS

* Hermes 使用 `[data-slot="..."]` 标记关键 DOM 节点

* 当前已知的相关 selector 包括：


  * `[data-slot="composer-status-stack"]`

  * `[data-slot="status-stack-section"]`

  * `[data-slot="status-row"]`

  * `[data-slot="aui_assistant-message-content"]`

  * `[data-slot="code-card"]`

  * 工具调用卡片可能通过 `.status-row`、`[data-slot="status-row"]` 或类似结构渲染

* 我**不能修改 Hermes 原生 HTML 结构**，只能通过 CSS 覆盖

* CSS 总大小有限制（约 25KB），需要精简

* 请优先使用 `[data-slot="..."]` 精确选择器，不要用 `.card` `.box` 这种宽泛 class

* 错误状态可能通过 `.codicon-error`、`role="alert"`、或特定颜色 class 标记
